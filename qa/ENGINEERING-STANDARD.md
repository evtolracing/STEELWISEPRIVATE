# Enterprise excellence program: permanent engineering and quality standard

Set by the owner on 2026-11-12. Applies to every phase, workstream and future ticket. This is the owner's text, condensed only in layout. Where a later instruction from the owner differs, the later instruction wins.

**Primary directive.** STEELWISE is an ERP/MES platform for metals, plastics, industrial supplies and multi-location service-center operations, designed and validated for about 80 locations and multiple divisions. Working is not the same as excellent. Passing a build is not production-ready. A completed ticket is not a verified business workflow. Every change is examined in the context of the whole application.

1. **Preserve the existing system.** React and Material UI; JavaScript/JSX only, no TypeScript; existing backend, PostgreSQL, service boundaries, API conventions, RBAC and tenant/location controls; existing working workflows. Never replace working functionality with placeholders or mocks. No unnecessary rewrites.
2. **Investigate before implementing.** Inspect the implementation, find the actual problem, review connected modules and prior tickets, trace data flows, identify affected APIs, tables, roles and tests, and define expected behaviour and measurable acceptance criteria. The first symptom is not assumed to be the root cause.
3. **Look beyond obvious bugs.** Substandard implementations, missing safeguards, inefficient workflows, inconsistency, incomplete features, fragile integrations, poor error recovery, missing information, excessive manual steps, duplicated logic, security weaknesses, scalability and performance risks, poor usability, thin test coverage. Separate objectively wrong behaviour from preference.
4. **Implement complete corrections** at the root cause. Check frontend, backend, API, database, validation, business logic, permissions, background jobs, events, notifications, reports, customer portal, documentation and tests. No inconsistent connected functionality, no duplicate implementations, no weakened validation.
5. **Verify complete operational behaviour.** Test the whole affected workflow, normal and exceptional, in an isolated environment, not only the changed function.
6. **Permanent regression protection.** Every confirmed defect gets an automated regression test where technically feasible, proving the previously failing behaviour. Run existing tests after every material change. Never disable tests or hide failures.
7. **Data and transaction integrity.** Inventory and financial accuracy, referential integrity, location and tenant isolation, traceability, status transitions, auditability, transaction safety. Test concurrency, retries, duplicate events and partial failures. Never fabricate or silently alter business data.
8. **Safe execution.** Isolated environments and synthetic data. No production mutation in simulations. No destructive migrations without approval. No real notifications, financial transactions or shipping instructions from tests. Ask when a business rule is ambiguous or a change is operationally material.
9. **No unverified completion claims.** Completion needs execution evidence. No invented results, coverage or measurements. Untested areas are marked NOT VERIFIED.
10. **No silently unfinished work.** Every finding has one recorded disposition: fixed and verified; fixed awaiting verification; assigned to a later phase with acceptance criteria; blocked by a documented dependency; requires a business decision; accepted risk with explicit approval; not applicable with justification. A finding assigned onward keeps its id, workstream, dependencies and verification requirements.
11. **Formal phase completion gate.** Each phase produces: scope and discovery; findings register; root-cause analysis; changes; files modified; database changes; tests added; tests actually executed; regression results; connected-module verification; remaining findings and blockers; explicit status. Statuses: VERIFIED COMPLETE, IMPLEMENTED — VERIFICATION INCOMPLETE, PARTIALLY COMPLETE, BLOCKED, FAILED. Only VERIFIED COMPLETE is a pass.
12. **Continuity across sessions.** Keep persistent progress files. Before each phase read the previous phase report, findings register, scorecard, traceability matrix, regression results and unresolved findings. Resume from recorded progress.
13. **Continue through safe, authorized work.** Do not stop at recommendations: implement, test, fix, re-verify until the acceptance criteria are met or a real blocker is hit. Save the exact continuation point when a session ends. Do not claim work will continue afterwards unless a mechanism exists.
14. **World-class production standards.** Each module is measured on functional correctness, data integrity, reliability, security, performance, operational efficiency, user experience, maintainability, accessibility, integration quality, observability and recovery readiness. A score never overrides a failed critical requirement. Goal: zero known unresolved critical defects and no known broken required workflow at release. Report tested scope and remaining uncertainty accurately.
15. **Final principle.** Do not confuse activity with completion, implementation with verification, or a clean test run with proof that every failure is gone.
